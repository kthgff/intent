## Description
Prove the spine end-to-end with zero LLM spend: fixture tickets repo
(tmp git repo w/ tickets in each starting status) + mock adapter
scripted per stage. Drive `imported → triage → needs-info → (answers)
→ ready → prd-draft → …` through the full transition chain to a PR on a
fixture code repo — each gate cleared by test code simulating the human.
Then negative paths: garbage sentinel → run_failed → retry ladder;
lint failure → doc-repair; killed run → stalled → retry.

## File ownership
`fixtures/**`, `packages/conductor/test/e2e/**`

## Acceptance criteria
- [x] One command (`pnpm test:e2e`) runs the whole pipeline green
- [x] events.jsonl in fixture repo shows complete, ordered event chain
- [x] Every gate mode (full|plan-package|minimal) exercised
- [x] Runtime reasonable (<5min); no real backends, git, or network

## Notes (implementation decisions — wp-040)

### Test harness
- `packages/conductor/test/helpers/fixtures.ts` — `makeFixtureWorld()`:
  copies `fixtures/{tickets-repo,code-repo}` to tmp, `git init`s both,
  adds a bare `file://` remote for the tickets repo (real
  pull-rebase/push coverage, no network), SqliteStore on tmp, boots
  `Conductor` + `RealTransitionHandler` + `ScriptedAdapter`.
- `ScriptedAdapter` wraps MockAdapter (real detached children) and
  routes a `(subject, stage, attempt) → spec` script. Specs encode as
  `MOCK_SCENARIO=script:<base64url JSON>` handled by
  `test/helpers/mock-agent.mjs` — a superset of the shipped agent that
  also writes absolute `files` (ticket-dir docs like tdd.md/test.md,
  which transition rows lint from the ticket dir, not run artifacts)
  and emits arbitrary sentinels.
- Helpers: `tick`, `runToStatus`, `waitForGate`, `clearGate`
  (clears gate_items + commits Q&A answers like the API would),
  `readTicket`, `diskStatus`, `eventsFor`, `ledgerFor` (events.jsonl).

### Bugs found in conductor machinery — fixed in scope
1. **Killed runs stranded tickets** (`reconcile/index.ts`): the timeout
   sweep's `killRun` and the exit-124 collect path emitted `run_killed`
   but never re-entered the retry ladder — a killed triage/design run
   left the ticket on its (transient) status forever. Both now call
   `applyRetryLadder` (CONDUCTOR "status stays for retry" + "transient
   run failure → 1 auto-retry").
2. **`launch` crashed on `verify`** (`launch/index.ts`): verify runs
   requested by `implementDone` went through `adapter.prepare` →
   `renderPrompt('verify')` throws (verify has no prompt template —
   CONDUCTOR "no agent involved"). launch now synthesizes a bare
   ARTIFACT_TARGETS prompt for verify.
3. **Worktree per-run vs per-ticket** (`launch/index.ts`): every
   repo-executing run did `git worktree add … ticket/<id>`, which fails
   once implement's worktree holds the branch — verify/fix/rebase could
   never run. Launch now reuses the existing `ticket_repos` worktree.
4. **Stale `gateCleared` disposition** (`transitions/handler.ts`):
   `gateCleared` read `ticket.status` (the projection snapshot), not the
   loop-advanced `status` — under `minimal`/`plan-package`, a `continue`
   chain into `test-approved` wrongly surfaced a suppressed
   `test-approved` gate_items row. Now uses the loop status.
5. **`spec_hash` self-invalidation** (`transitions/actions.ts`):
   `recordSpecHash` appends `spec_hash:` to ticket.md AFTER hashing;
   re-hash then included the line → every ticket stalled at
   `test-approved` on a permanent stale-spec gate. `specInputsHash` now
   strips the `spec_hash` line from ticket.md before hashing.
6. **stale-spec / gate_approved event spam** (`transitions/handler.ts`):
   while parked on a stale spec, each tick emitted `note_added` +
   `gate_approved` again. Stale check now runs before the gate event and
   the gate item is surfaced once.
7. **`events.jsonl` never written** (`events/index.ts`,
   `contracts.ts`): PRD §ticket-folder + DB-SCHEMA make
   `tickets/<id>/events.jsonl` the git-side ledger (events_idx its
   projection) and LOG.md its generated mirror — nothing wrote the file.
   `regenerateLog` now writes events.jsonl (SCHEMAS §7 shape, seq order)
   before LOG.md; `emitEvent` regenerates on each emitted ticket event,
   and `applyTicketStatus` regenerates after its status_changed append so
   store-direct paths (run_failed ladder tail) also land.

### Ambiguities / non-goals
- E2E stops at `pr-open` — pushing PRs + `ci-watch`→`merged` is the
  shepherd's job (wp-051); the table treats a cleared ci-watch gate as
  "human merged".
- `gates: full` is the happy-path mode; `minimal` and `plan-package`
  are separate tests over SR-0003 (`ready`).
- Runtime: `pnpm test:e2e` ≈ 15s total (happy path ≈ 5s).
